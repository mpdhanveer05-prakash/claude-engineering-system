# PRD Draft

**Goal:** Produce a PRD that's ready for engineering and design review.
**When to use:** New feature with non-trivial scope.
**Inputs:** problem statement, target users, success metric, constraints.
**Output shape:** Markdown PRD per `docs/product/PRD-v1.md` template.
**Stop conditions:** No solutioning before the problem is sharp.

---

Draft a PRD for: {FEATURE}

Inputs you've been given:
- Problem: {PROBLEM}
- Target user: {USER}
- Success metric: {METRIC}
- Constraints: {CONSTRAINTS}

Process:
1. Sharpen the problem — one paragraph, no jargon, name the pain.
2. List user jobs-to-be-done with frequency + intensity.
3. List non-goals explicitly (the most underused section).
4. Functional requirements as MoSCoW.
5. Non-functional requirements with concrete numbers.
6. Top 3 risks with mitigations.
7. Quantitative success criteria (X improves from Y to Z within N days).
8. Rollout plan (flag + cohorts).
9. Open questions you can't resolve without more input.

No marketing prose. Each section answers a specific question.
